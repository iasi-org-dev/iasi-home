EXTENSIONES LUA PARA QUARTO

IASI Lua: Capacidades reutilizables dentro de Quarto

La plataforma Lua de IASI para extender el renderizado de Quarto con capacidades especializadas, compartiendo un núcleo común y generando extensiones autónomas para los proyectos consumidores.

Abrir User Guide Ver repositorio ↗

Overview

iasi-lua reúne las extensiones Lua de IASI para Quarto. La fuente se organiza alrededor de un core compartido y de directorios independientes por extensión; el build materializa distribuciones Quarto autocontenidas bajo _extensions/.

La regla es sencilla: la fuente se mantiene una vez y la distribución se genera. Los proyectos consumidores instalan y cargan las extensiones resultantes sin depender de la estructura interna del repositorio.

Core

Proporciona infraestructura común de configuración, motor, caché, filesystem, metadatos y mediabag.

Extensión

Cada capacidad mantiene únicamente su lógica específica y su manifiesto Quarto.

Build

Combina el core y la extensión para producir una distribución autónoma.

Consume

Quarto carga la extensión generada como un filtro normal dentro del proyecto.

Extensiones

IASI PlantUML

Convierte diagramas PlantUML escritos como código en imágenes integradas durante el renderizado.

filters:
  - iasi-plantuml

Incluye configuración del servidor, formato de salida, caché y estilos compartidos.

IASI Shiny

Integra aplicaciones Shiny para R en publicaciones HTML estáticas mediante Shinylive y webR.

filters:
  - iasi-shiny

Permite incorporar bloques interactivos sin convertir la publicación completa en un servidor Shiny.

Ciclo de desarrollo

Toda la automatización del proyecto se mantiene en Bash.

core/ + extensión
       ↓
./scripts/build-all.sh
       ↓
_extensions/
       ↓
./scripts/check-generated.sh
./scripts/check-versions.sh
./scripts/test-all.sh
       ↓
./scripts/install-local.sh <proyecto>
       ↓
proyecto Quarto consumidor

También puede construirse una única extensión:

./scripts/build-extension.sh plantuml

En Windows, este ciclo se ejecuta desde WSL u otro entorno Bash compatible.

Modelo fuente → distribución

software/iasi-lua/
├── core/                 plataforma Lua compartida
├── plantuml/             fuente de IASI PlantUML
├── shiny/                fuente de IASI Shiny
├── scripts/              automatización de build, checks y tests
└── _extensions/          distribuciones Quarto generadas
    ├── iasi-plantuml/
    └── iasi-shiny/

_extensions/ no es fuente de desarrollo. No se edita manualmente: cada distribución se vuelve a materializar desde core/ y desde el directorio fuente de su extensión.

Ese límite mantiene separadas dos responsabilidades:

fuente mantenible
      ↓ build
distribución instalable
